# 烟花爆竹全链条数字化预警监管平台 · 系统说明

> 对应工程目录：`risk/`（6 个运行版页面）、`risk-src/`（模块化源码版）
> 共享数据模型：`shared/patent-model.js`

---

## 一、系统定位

对烟花爆竹**仓储环节**，利用已有的**扫码出入库数据**与新增的**车辆定位轨迹数据**，
在同一条监测时间轴上依次完成 5 项计算与判定，输出两类风险结论：

- **隐蔽囤货风险** —— 账面库存已满、车辆滞留不散，实际库存可能超过账面
- **账面造假风险** —— 库存出现下降，但监控中并无车辆驶离，下降可能来自账目而非实物

系统的价值在于：把原本需要在两个独立系统中分别查看的「台账数据」与「轨迹数据」，
放到**同一条时间轴**上相互印证，从而识别单看任一项都发现不了的风险。

---

## 二、5 项核心功能与时间线

监测时间轴共 60 分钟（T+0 ~ T+60′），划分为 5 个首尾相接的阶段：

| 阶段 | 时间区间 | 功能 | 核心输出 |
| --- | --- | --- | --- |
| **S1** | T+0 ~ 9′ | 库存饱和度计算 | 饱和度 `S(t) = Q(t) / C` |
| **S2** | T+9 ~ 17′ | 电子围栏与车辆轨迹 | 围栏内车辆定位轨迹、围栏内车辆集合 `V_in(t)` |
| **S3** | T+17 ~ 32′ | 滞留车辆筛选与滞留指数 | 滞留车辆集合 `V_stay(t)`、异常滞留指数 `I(t)` |
| **S4** | T+32 ~ 41′ | 双风险判定 | `Risk_Hidden`、`Risk_Phantom` |
| **S5** | T+41 ~ 56′ | 置信度校验与管控预警 | 置信度 `C(t)`、管控预警 + GIS 坐标呈现 |

对应页面：`patent-s1.html` ~ `patent-s5.html`，总览页为 `patent.html`。

## 三、阈值参数（实现见 `risk-src/js/core/01-params.js`）

全部判定阈值集中在参数集 `P` 中声明，**独立于算法实现**，
支持按不同仓储类型（1.3 级工库房 / 中转库 / 零售库）整组替换而不改动任何算法代码。

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| `capacity` | 800 吨 | 目标仓储设计容量（饱和度分母） |
| `fullRatio` | 0.85 | **满载阈值**：`S(t) ≥ 0.85` 视为达到满载 |
| `staticSpeed` | 2 km/h | **静止阈值**：瞬时速度低于该值视为静止 |
| `tolerance` | 15 min | **装卸容忍时间**：正常装卸的最长合理耗时，超过即视为滞留 |
| `stayThreshold` | 0.60 | **滞留报警阈值**：`I(t) ≥ 0.60` 视为滞留异常 |
| `confThreshold` | 0.85 | **置信度阈值**：多源数据一致性校验通过线 |
| `fenceR` | 0.0082 度（约 800 m） | 地理电子围栏半径 |
| `bookDrop` | 0.15 | 账面造假考察窗口内的饱和度下降阈值（15%） |
| `stock0` | 498 吨 | T+0 时刻初始库存 |
| `BOOK_WIN` | 36.8 min | 账面造假考察窗口起点 |

## 四、两条判定式

判定式是整个方案的核心，已从内联表达式提炼为可独立评审的函数
（`risk-src/js/core/09-s4-dual-risk.js`）。

### 判定式 A —— 隐蔽囤货风险

```
Risk_Hidden  ⟺  S(t) ≥ fullRatio  ∧  I(t) ≥ stayThreshold
```

即：**库存已达满载，同时围栏内车辆异常滞留**。
单独看任一项都很常见（库存满或车辆多），两者同时成立才指向「货已入仓但不销账」。

### 判定式 B —— 账面造假风险

```
Risk_Phantom ⟺  ΔS < −bookDrop  ∧  ¬∃ 驶离轨迹
```

即：**在考察窗口 `BOOK_WIN` 之后，饱和度出现超过 15% 的下降，但围栏内没有任何车辆驶离**。
`BOOK_WIN = 36.8′` 的作用是把「正常装卸后离场」与「风险窗口内的异常离场」区分开 ——
只有窗口之后才开始驶离的车辆才计入驶离轨迹。

### 实算判定时刻（本数据模型下）

| 结论 | 触发时刻 |
| --- | --- |
| 隐蔽囤货风险成立 | **T+32.0′** |
| 账面造假风险成立 | **T+40.6′** |
| 管控预警发布 | **T+41.0′** |

这三个时刻由时间线预计算得出，写入 `DERIVED.riskHideFrom` / `bookFrom` / `alertFrom`。

## 五、置信度校验（S5）

风险判定成立后并不直接出预警，而是先做**多源数据一致性校验**：

```
C(t) = w₁ · 地图匹配度 + w₂ · 围栏内车辆数匹配度 + w₃ · 时间戳连续性 + w₄ · 台账记录匹配度
```

`C(t) ≥ confThreshold`（85%）时校验通过，确认风险成立，生成管控预警信息，
并在 GIS 地图上同时显示**目标仓储坐标**与**对应运输车辆坐标**。

置信度的作用是抑制误报：当某一数据源（如轨迹）缺失或时间戳断裂时，
即使两条判定式都命中，也不会直接发出预警。

---

## 六、关键设计：判定结果与帧序解耦

所有指标都实现为**监测时刻 t 的纯函数**，风险判定采用
「**预计算时间线 + 峰值锁存**」而非逐帧增量判断：

```
加载期：11-timeline.js 一次性扫过全时间线，锁存各判定式的首次命中时刻
运行期：任意时刻 t 只需查表 / 求值，不做累加、不依赖上一帧
```

由此得到两个性质：

1. **判定结果与帧序、播放速度、页面刷新完全无关** —— 无论从哪一页进入、
   无论浏览器掉帧到什么程度，三个判定时刻都是 32.0′ / 40.6′ / 41.0′。
2. **任意时刻可瞬时冻结** —— 页面外壳提供 `window.__setT(t)`，
   可把界面冻结到任意监测时刻并重绘，这是界面等价性自检可复现的前提。

## 七、页面运行行为

| 行为 | 说明 |
| --- | --- |
| 进页起点 | 统一从 **T+0** 起播（跨页时刻连续性已取消） |
| 播放方式 | **自动播放**，无播放按钮、无进度条、无阶段条 |
| 推进速率 | 约 3 倍速，60 分钟时间线约 17 秒一轮 |
| 循环 | 播放到底自动回到 T+0 重新开始 |
| 保留控件 | 「重置」按钮 |
| 缩放 | 1920 × 1080 设计稿，`fitScreen()` 等比缩放 |

> 若删除页面中的区块导致 `.screen` 纵向分配变化，
> 必须在启动时补一次 `setTimeout(relayout, 220)` ——
> 否则 ECharts 初始化读到的容器高度与最终布局不符，画布会残留约 4px 溢出。

## 八、两套页面：运行版与源码版

| | `risk/`（运行版） | `risk-src/pages/`（源码版） |
| --- | --- | --- |
| 数据模型 | `shared/patent-model.js`（单文件 507 行） | `risk-src/js/core/`（14 个模块） |
| 页面脚本 | 内嵌 `<script>` | 外链 `js/render/` + `js/pages/` |
| 样式 | 内嵌 `<style>` | `risk-src/css/platform.css` |
| 全局接口 | `window.PATENT` | `window.FWCore`，经兼容层导出为 `window.PATENT` |
| 适用场景 | 演示、交付 | 阅读算法、评审、二次开发 |

两版**数值行为完全等价**，由两项自动自检保证：

| 自检 | 入口 | 规模 | 结论 |
| --- | --- | --- | --- |
| 数值等价 | `risk-src/tools/equivalence-test.html` | 55,610 项 | 差异 0，最大绝对误差 0 |
| 界面等价 | `bash risk-src/tools/dom-diff.sh` | 115 组（5 页 × 23 冻结时刻） | 全部一致 |

源码结构与加载顺序（不可调整）详见 `risk-src/README.md`；
技术特征与源码的逐项对应详见 `技术特征对照表.md`。
